# 拾页 · 本地小红书素材工作台

## 已确认的第一版

- 仅本机访问；首次初始化一个管理员。React/TypeScript/Vite 前端，Python/FastAPI 后端，SQLAlchemy/SQLite 数据库，独立 Python 任务进程。
- 连接一个小红书账号；登录失效时暂停采集，网页扫码后加密保存新凭据并续跑。限流/验证码与登录失效分别处理。
- 单条、批量、作者、收藏以及既有关键词采集能力。进度持久化；重启恢复运行中的任务；主动暂停、取消保持不变。
- 自动扫描现有媒体目录导入历史笔记，保持原目录。按笔记 ID 去重，已有资料默认跳过、缺失媒体补齐；刷新不改变个人标签及文件夹关系。
- 图文取第一张本地图，视频取已有 cover。整个笔记是整理单位，多文件夹关联、多层文件夹、拖拽及等效按钮操作。
- 总素材库、类型/原始标签/个人标签筛选、正文及 OCR 搜索、回收站。清空回收站才移除文件；删除文件夹仅删除分类。
- 采集结果、素材库和文件夹均打开同一个大详情弹层；左图集/视频，右作者、正文、标签、统计、OCR 和整理操作。关闭保留列表位置。
- 手动 OCR；设置服务地址、模型、Key 和连接测试；第一版模型仅用于 OCR。沿用在线 PaddleOCR 协议。
- 沿用现有 TXT/JSON、detail/info、原图及 PNG、视频及音频、OCR Markdown 和 Excel 输出。浏览器多文件下载仅使用 ZIP 作为运输容器，不更改内部格式。
- 评论全文后续扩展；首版展示已采集的评论数。

## 实现原则

数据库记录笔记与关联及任务检查点，媒体在本地文件系统。数据库、密钥、Cookie、OCR Token、采集数据不进入 Git。独立 worker 以单实例文件锁保护；任务控制在网络/文件操作边界检查。下载先落临时文件再原子改名，任务恢复以已完成文件为界。

## 界面方向

本地设计检索返回的营销/教育模板不适合此场景，因此使用已确认布局与用户详情截图作为依据。浅暖灰背景、白色卡片、深墨文字和朱红强调色，窄侧栏和清晰文件树，封面内容优先。优先中文可读性；标题采用衬线中文气质，操作文字采用本机中文无衬线字体。键盘可达、焦点可见、弹层焦点管理、拖拽等效菜单、减少动态效果。

## 扫码确认流程修复（2026-09-03）

- 统一使用原生二维码状态接口 `/api/sns/web/v1/login/qrcode/status`，读取 `code_status` 及 `login_info.session`，不再将另一套确认接口与二次凭据交换混用。
- 新凭据始终替换旧值；手机确认后只校验账号，拒绝游客会话、缺失用户 ID 或缺失 session。
- 临时账号校验错误最多重试 3 次、最长 45 秒；失败返回明确终态，前端停止轮询。成功结果可重复读取，避免响应丢失后显示二维码过期。
- 验证成功后自动关闭扫码弹窗、刷新账号状态并进入总素材库首页，无须点击“完成”。
- 手机确认后的现场响应为 HTTP 471，同时 JSON 含 `success: true, code: 0`，没有有效登录数据。HTTP 状态优先于业务字段，二维码创建、状态查询、账号检查均将此识别为平台拦截；不再显示“错误码 0”或把它放行成新登录成功。
- 本次扫码受限时，若本机保存了原账号凭据，自动重新请求账号接口校验。仅在确认非游客、用户 ID 与原账号一致时继续使用旧登录并返回首页；不覆盖 Cookie，不把本次扫码标记为已更新凭据。校验不通过则保留任务及原凭据，提示检查官网安全验证。正常扫码成功仍保存新凭据。
- 诊断日志仅记录 HTTP 状态、业务码、响应字段类型及必要布尔状态，不输出 Cookie、二维码参数、session 或用户资料。
- 36 项 Python 回归检查及前端构建通过。已现场验证原账号的已保存登录返回 HTTP 200、有效非游客账号；本次新二维码的凭据交换仍受小红书 HTTP 471 限制，未宣称其成功。
